# Доступи SpeedLabor

Підтримується PocketBase **0.40.4**. Dockerfile закріплює цю версію.
Міграція призначена для наявної бази LagerApp з колекціями `users`, `parts`,
`locations`, `inventory`, `transactions`. Вона не створює новий порожній склад
і не змінює наявні кількості чи старі рухи.

## Права

| Операція | Працівник | Адміністратор |
| --- | --- | --- |
| Пошук, залишки, фото, журнал, звіти | Так | Так |
| Створення й редагування деталей та комірок | Так | Так |
| Прихід і видача | Так | Так |
| Коригування залишку з причиною | Ні | Так |
| Створення облікових записів, ролі, блокування, зміна пароля | Ні | Так |
| Видалення невикористаних деталей та комірок | Ні | Так |

Реєстрація для гостей закрита. Правила перевіряються в PocketBase, незалежно
від інтерфейсу. Блокування одразу закриває API навіть для вже виданого токена;
інтерфейс перевіряє обліковий запис при поверненні у вікно та раз на хвилину.
Облікові записи блокуються, а не видаляються. Рухи журналу не редагуються й не
видаляються через застосунок; виправлення оформлюються окремим коригуванням.
Технічний superuser PocketBase має аварійний доступ і не є повсякденною роллю.

## Оновлення наявного складу

1. Запустіть Docker Desktop. Перед оновленням зупиніть запис у склад.
2. У PowerShell у `D:\SpeedLabor\LagerApp` зупиніть PocketBase й зробіть копію
   всієї папки `pb_data` (SQLite, допоміжна база та фото):

   ```powershell
   docker compose stop pocketbase
   $warehouseBackup = "D:\SpeedLabor\LagerApp\pb_data-backup-$(Get-Date -Format yyyyMMdd-HHmmss)"
   Copy-Item -LiteralPath 'D:\SpeedLabor\LagerApp\pb_data' -Destination $warehouseBackup -Recurse
   ```

3. Запустіть оновлений сервер:

   ```powershell
   docker compose up --build -d pocketbase
   docker compose logs --tail 50 pocketbase
   ```

   Міграція застосовується автоматично й атомарно при запуску. Якщо у старій
   базі є дублікати пар «деталь + комірка», унікальний індекс зупинить міграцію
   без часткового застосування. Потрібно перевірити такі записи, а не видаляти
   їх автоматично.

4. Запустіть інтерфейс через `npm run dev` у `lager-app`, або зберіть контейнер
   `docker compose up --build -d app`. За замовчуванням API використовує ту
   саму адресу комп’ютера, за якою відкрито застосунок, з портом `8090`.
   Телефон має бути в тій самій локальній мережі; відкривайте IP комп’ютера,
   а не `localhost`. Якщо API розміщено окремо, для контейнерної збірки задайте
   `POCKETBASE_URL` як адресу API, доступну з браузерів працівників. Для `npm run dev`
   відповідне налаштування — `NEXT_PUBLIC_POCKETBASE_URL` у `.env.local`.
5. Відкрийте `/setup` у застосунку. Введіть чинні дані власника PocketBase та
   окремі ім’я, email і новий пароль адміністратора складу. Токен власника
   використовується лише в пам’яті цієї форми, не зберігається в localStorage.
   Коли активний адміністратор уже існує, форма запропонує звичайний вхід.
6. Увійдіть через `/login`, відкрийте **Працівники** й створіть облікові записи.
   Для роботи з телефона налаштуйте HTTPS: він потрібен для захисту паролів
   і доступу до камери.

Пароль superuser, що раніше був у `docker-compose.yml`, видалено з конфігурації.
Це **не змінює пароль у наявній базі**. Власнику потрібно змінити його в
адмінпанелі PocketBase (`/_/`). Нових стандартних паролів немає.

## Складські операції

`POST /api/warehouse/movements` приймає `type` (`incoming`, `outgoing`,
`adjustment`), `part_id`, `location_id`, `qty`, `notes`, `operation_id`.
Для коригування `qty` означає новий фактичний залишок, а причина обов’язкова.
Для приходу/видачі кількість має бути додатною; дробові значення підтримуються.

Операція в одній транзакції перевіряє актуальні права, читає залишок, оновлює
його та зберігає рух із серверним автором і підсумковою кількістю. Від’ємний
залишок заборонений. Повторення того самого `operation_id` і параметрів повертає
попередній результат. Інші параметри з цим ID відхиляються. Клієнт зберігає ID
незавершеного запиту в sessionStorage для повтору після втрати відповіді.

Створення картки деталі й початковий прихід — окремі операції. Якщо прихід
не завершився, картка залишається; повідомлення дозволяє повторити прихід
без повторного створення картки на цій сторінці. Старі рухи без автора
відображаються як створені до впровадження облікових записів.

Поле `parts.min_qty` задає поріг «Мало» для всієї деталі. Його змінює лише
адміністратор. Значення `0` вимикає контроль. Звіт підсумовує залишок деталі
в усіх комірках; деталь потрапляє до «Мало», коли загальна кількість менша
або дорівнює порогу. Деталі без комірки також входять у звіт із залишком 0.

## Перевірка

```powershell
npm run build
npm run test:access
```

Інтеграційні тести запускають справжній PocketBase на випадковому локальному
порту з тимчасовою базою `.local-tools/access-test-*`. Робочі дані не
використовуються. За замовчуванням виконуваний файл очікується в
`.local-tools/pocketbase-0.40.4/pocketbase.exe`; інший шлях задається змінною
`POCKETBASE_BINARY`.

Для перевірки браузером після production-збірки:

```powershell
npm install --prefix .local-tools/browser playwright --no-audit --no-fund
$env:CHROMIUM_BINARY = 'C:\path\to\chrome.exe'
$env:BROWSER_TEST = '1'
npm run test:access
```

Браузерні тести перенаправляють усі API-запити на тимчасову базу; не надсилають
операції на адресу з `.env.local`. Тимчасові бази та знімки екрана залишаються
в `.local-tools`, яка виключена з Git і Docker-контексту.

Автоматичного відкочування цієї міграції немає: воно відкрило б анонімний
доступ і видалило б дані авторства. Для аварійного відновлення зупиніть сервер,
збережіть поточну базу окремо й відновіть перевірену резервну копію разом із
сумісною попередньою версією застосунку та PocketBase.
